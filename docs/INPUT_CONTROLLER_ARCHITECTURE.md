# 入力コントローラーの責務と状態の寿命

Issue #45では機能・入力ソース識別子・設定保存先を変更せず、既存の処理を以下へ分割した。

| 型 | 責務 | 所有者・寿命 |
| --- | --- | --- |
| `SumibiInputController` | IMKイベント受付、キー解釈、入力先選択、処理の接続 | IMKが生成する短命のコントローラー |
| `InputRuntime` | 有効な入力経路の状態と最新・直前のコントローラーへの接続 | プロセス共有。実際の入力先変更で追跡を破棄 |
| `InputSession` | 未確定文字列、要求ID、待機キー、候補の状態機械 | Runtimeが保持。OSに依存しないCore |
| `TextReplacementTracker` | 文字列・範囲の照合、遅延したカーソルや折り返しの補正 | Runtimeが保持。入力先を読むだけで書き込まない |
| `ConversionLifecycle` | 通信タスク、届いた応答、再試行タイマーの開始・キャンセル | Runtimeが保持。入力先には書き込まない |
| `CandidatePresenter` | 候補窓の表示状態、選択位置、表示位置、辞書注記 | Runtimeが保持。実ウィンドウは遅延生成 |
| `InputEffectApplier` | 状態機械の効果を明示された入力先へ適用 | 呼び出しごとの値。独立した追跡状態は持たない |

## なぜ共有するか

この開発環境のmacOS 27では、IMEがキーを消費した直後にもコントローラーが終了・再生成されることを観測している。コントローラーの寿命を文書や入力欄の寿命とみなすと、入力途中の状態・非同期応答・候補窓を失う。そのためRuntimeと各処理の所有者は、短いセッション再生成をまたいで保持する。

これは複数の文書の状態を同時に管理する実装ではない。既存の入力先変更・対象外アプリ・Escの処理で通信とタイマーを取り消し、要求IDと入力先の範囲・原文の照合で古い応答や異なる文字列の置換を拒否する。コントローラー再生成と実際の入力先変更を区別する。他のOS・入力先での挙動は実機確認が必要。

## スレッドと応答の順序

Runtime、InputSession、置換照合、候補窓、IMKへのアクセスはメインスレッドから扱う。既存のIMKアダプターのSwift 5言語モードを維持しており、型全体へのactor隔離の変更はこの作業では行わない。通信は非同期で実行し、応答の保存・反映は`MainActor.run`へ戻す。

応答は現在の要求IDと一致する場合だけ保存する。入力先が一時的に無効な場合は0.25秒ごとに最大240回再試行する。入力先の照合後に応答を一度だけ取り出し、次の待機キーを排出する前に旧タイマーとタスクを解除する。Escは応答の反映より先に処理し、待機文字を保留へ救済し、待機中の制御キーは実行しない。

候補選択のコールバックはコントローラーを弱参照する。Runtime・候補窓へRuntime自身を保持するコールバックを渡して循環参照を作らない。

## 検証

Issue #45でCoreの75テストにIME側20テストを追加した。範囲・原文不一致、UTF-16、折り返し、読取範囲制限、選択範囲変更、応答の一度だけの受取、キャンセル後の遅延応答、再試行の取消・上限、候補の選択・巡回を検証する。Issue #46ではさらに設定・Keychain・入力先への書き込み・送信同意のテストを追加した。現行の件数・再実行方法と自動化範囲は[テスト手順](../Tests/README.md)を参照する。テストは実API、実IME登録、実ユーザーの設定・Keychainを使用しない。

2026-10-04、開発署名付きのリファクタリング版へ入れ替え、利用者が「今までと同じ動作になりました」と確認した。案内した確認範囲は通常変換・追加候補の選択・Escでの下線解除・変換待ち中の追加入力。最初の報告ではアプリ名は特定していないが、その後、Codexアプリ内でも同じ確認をして問題がなかったと利用者が報告した。これは今回の操作についての回帰確認であり、既存の長文読取制限の解消を意味しない。

自動テストは実際のIMK接続を置き換えるものではない。以下は追加の実機確認項目であり、今回の報告だけではすべて確認済みとは扱わない。

- メモまたはTextEdit：通常変換、候補選択、原文へ戻すUndo、Escで下線だけ解除、次のEscがアプリへ届く。
- ターミナル.appのzsh：変換、追加候補、候補の巡回、折り返す入力。
- Chrome系入力欄：変換直後の候補選択、選択範囲の変換。長文の読取制限は回避した扱いにしない。
- 通信待ち中：文字入力、Esc、別アプリへの切り替えで原文を失わず、遅延応答が別の入力先へ書き込まれない。

実機版への入れ替えは、利用者がABCなど別の入力ソースへ切り替えてから行う。Issue #45は、PR #49の責務分割・利用者の実機確認と、PR #50（#46）のテスト補強を根拠にクローズした。残る手動確認項目をすべて完了した意味ではない。#47での名称整理・更新確認は[ビルドモード](BUILD_MODES.md)、現行実装と要件の差は[照合記録](IMPLEMENTATION_AUDIT.md)を参照。
