# 変換中・エラーの知らせ方（Issue #12）

状態: #12の作業版で実装。利用者が実機で変換中のアイコン表示とエラー時の動作が期待どおりであることを確認済み。エラーの発生方法・種類や外部プロバイダーでの検証条件は報告されていないため、全種類・全環境を確認済みとは扱わない。通知・音・自動ポップアップや入力先へのエラー文字列の挿入は行わない。

## 表示と解除

- 通常時は従来のSumibiアイコン。変換要求から結果の反映待ちまで、右下に砂時計の印を付ける。クリックすると「変換中…（入力は続けられます）」を表示する。
- エラーがある場合は感嘆符の印を優先する。クリックした専用メニューバーメニューで、直近のエラーの種類・原因・対処を表示する。変換中でも過去のエラーが残る場合は、メニューとアクセシビリティラベルで両方を区別する。
- 最新のエラー1件だけをメモリに保持する。履歴を永続保存しない。後続のエラーは置き換える。クリック・次の変換・成功では自動解除せず、「エラー表示を解除」で消す。プロセス終了でも消える。
- 解除するのは表示だけで、要求・原文・待機文字・候補を変更しない。エラー確認を入力や回復処理の再開条件にしない。フォーカスを奪うウィンドウは開かない。
- 通常のIMEメニューにも短いエラー名を残す。保留文字・未適用制御キーの救済処理そのものは変更しない。

## エラーの種類と秘密情報

通信失敗・タイムアウト・1,000文字超過・APIキー未設定／読込不能をそれぞれ別の説明にする。送信同意なし、URL不正、認証エラー、利用制限、サーバーエラー、不正／空の応答、入力先接続不能・選択文字列の読取不能も固定の原因・対処文で知らせる。

原文、周辺文脈、辞書本文、APIキー、送信先URL、プロバイダーの応答本文は表示・保持しない。`.network(String)`の生の詳細や`localizedDescription`も表示に使わない。固定文への変換は[ConversionFeedback](../Sources/SumibiIME/MenuBar/ConversionFeedback.swift)で行う。エラー状態は入力の状態機械とは分離し、Runtimeが所有する。

[ConversionLifecycle](../Sources/SumibiIME/Conversion/ConversionLifecycle.swift)が待機状態を管理し、現行の要求IDと一致する通信失敗だけを通知する。失敗は応答が返った時点で表示するため、入力先の再接続や次のキー操作を待たない。取消済み・古い要求の失敗で印を付けない。入力先への反映待ちの再試行上限を超えた場合は、通信タイムアウトとは別の入力先エラーになる。

## 自動確認

[ConversionFeedbackTests](../Tests/SumibiIMETests/ConversionFeedbackTests.swift)の9件で、主要4種類の区別、全エラーの固定文、秘密情報の非表示、表示解除と入力処理の分離、原文の保持、取消後の遅延エラー無視、待機と表示の更新を検証する。

通常・開発構成の全テストは[Tests/README](../Tests/README.md)を参照する。メニューバーの描画や外部APIの実応答を自動確認した扱いにはしない。

### 実URLSessionの60秒タイムアウト

```sh
SUMIBI_RUN_TIMEOUT_TEST=1 SUMIBI_DEVELOPMENT_FEATURES=0 swift test --filter ConversionTimeoutIntegrationTests
```

[専用テスト](../Tests/SumibiIMETests/ConversionTimeoutIntegrationTests.swift)は127.0.0.1の一時ポートだけで接続を受け、HTTP応答を返さない。実URLSessionと通常のOpenAI互換クライアントを使うが、送るのはダミーキー・ダミーモデル・ダミー文字列だけ。ユーザーの設定・Keychain・実APIにはアクセスしない。通常の`swift test`ではこの1件を明示的にスキップする。

2026-10-04、60.04秒で`.timedOut`になったこと、原文と待機文字の保持、タイムアウトの説明、待機状態の解除を確認した。外部サービスのタイムアウトや実IMK接続を検証したことにはしない。

## 実機確認結果と追加の確認項目

2026-10-04、利用者がABCへ切り替えた後、旧版を退避して通常版を導入した。利用者から「アイコンが、変換中になることを確認しました」、続いて「エラー発生時の動作確認完了しました。期待動作です」と報告を得た。これは実機での表示・操作の確認であり、エラー全種類、外部サービスの60秒タイムアウト、明暗やアクセシビリティなどの全条件を検証済みという意味ではない。

以下は追加確認のチェックリスト。上記の報告だけで全項目を確認済みとはしない。

- 通常版で変換中の印と、APIキー未設定・文字数超過などの印を確認する。必要な設定変更は利用者自身の操作で行い、実キーの削除は確認のために強制しない。
- 専用アイコンをクリックし、原因・対処と「エラー表示を解除」が見えること、解除後のアイコン、入力先の原文保持を確認する。
- 明示的な開発版で`PrototypeResponseMode=failure`・`slow`・`timeout`を使い、模擬失敗・待機・タイムアウトを確認する。通常版はこれらの設定を無視する（[ビルドモード](BUILD_MODES.md)）。模擬timeoutは60秒後の成功を返す既存動作であり、失敗タイムアウトの実測の代わりには使わない。
- 本人が通常利用する実APIで成功時の待機表示を確認する。実APIの失敗を試す場合は料金・認証情報への影響を本人が確認し、ダミーキー等を使う。生のキーや原文をログ・スクリーンショットへ含めない。
- 明暗のメニューバーとアクセシビリティラベル、他アプリの入力中に自動的に画面が開かず、エラー確認を待たずに入力・回復処理が続くことを確認する。
