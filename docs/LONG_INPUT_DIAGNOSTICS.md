# Codexの長文変換と失敗診断（#56）

2026-10-08：自動判定は[Decisions方式](DECISIONS_CONVERSION.md)へ移行。
以下の実機結果は旧Jev版での履歴。原文の全文照合・失敗診断・解説は維持するが、
Decisions移行によって入力先アプリの長文読取制約を解消した意味ではない。

## 調査の状態

2026-10-06、利用者からCodexの入力欄で100文字以上を入力すると変換に失敗し、
その原因をメニューでも確認したいという報告を受けた。
現在の作業版では、利用者が121文字の自動変換失敗と、原文確定後の全文読取不能を
メニューで確認した。原文のまま残ったことも報告された。
続いて手動変換でも120文字の原文読取不能を捕捉した。
短文のCtrl＋Jによる変換と、Command＋Zを1回押して原文へ戻ることも利用者が確認した。
失敗捕捉・メニュー表示と短文・Undoの実機確認は完了。
入力先が全文を返さない根本理由の再確認は未完了で、長文変換自体を解消済みとはしない。

関連する[#41の実機調査](https://github.com/kiyoka/Sumibi-mac/issues/41#issuecomment-5969833513)
では、114文字の原文に対し末尾100 UTF-16単位だけが取得でき、前方14単位は
分割しても取得できなかった。全選択した114文字の変換は利用者が成功を確認した。
当時のChromium公開実装と一致したが、Codex内の正確なリビジョンとは未照合。
今回も同じ制約の可能性はあるが、現在の入力先の失敗原因と断定しない。

Sumibiには100文字の変換上限を追加していない。既存の手動変換要求の1,000文字制限と
Jev観測の512文字制限を維持する。文字数とUTF-16長は異なるため、両方を表示する。

## メニューの診断

常設メニューと入力ソース側のメニューで、固定文の原因・対処に加え、失敗段階と
対象文字数／UTF-16長を表示する。部分取得時は要求長／取得長も区別する。

100文字以上の原文の全文読取不能、または要求より短い部分取得で適用を中止した場合、
利用者が対処を選べるよう、両方のメニューに以下の固定文を追加する。

- 解説：一部のアプリでは、100文字以上のローマ字の文章を変換できない場合があります。
- 解説：Codexアプリで確認されています（原文全文を読み取れないため）。
- 解説：確定済みの長文は、変換対象だけを選択してCtrl＋Jを試す方法もあります。
- 対処：100文字未満の短い区切りで、こまめに変換してください。

100文字以上が常に失敗するという断定や、新しい変換上限ではなく、既知の互換性情報と
回避策の案内。短文、通信失敗、原文の内容不一致、原文取得後の別の失敗には付けない。
置換後の確認失敗にも付けず、変換済みなら再変換しないという既存の案内を維持する。
この追加文言は自動テストで確認した。2026-10-07、利用者がABCへ切り替えた後に
解説追加版へ更新し、「案内が表示されました」と実機表示の確認を得た。
この報告は案内の表示確認であり、長文変換の制約を解消した意味ではない。

| 段階 | 表示する確認事項 |
| --- | --- |
| 自動判定前の原文読取 | 未確定範囲の取得不能・長さ不一致・原文不一致は静かな「自動変換の見送り」。赤いエラーにせず、Jevへ送信しない |
| Jev判定 | 設定・認証・回数上限・通信・応答形式。従来の固定分類を維持 |
| 変換API | 送信前のキー・同意・文字数等と、通信／応答取得を区別 |
| 原文確定後 | 確定原文の読取不能・内容不一致・範囲不一致。自動変換の記録範囲／カーソル直前の読取長と固定比較分類も表示 |
| 適用前・置換直前 | 対象記録・範囲の取得不能、原文の読取不能・部分取得・不一致。置換しない |
| 置換後確認 | 読取不能・長さ不一致・内容不一致が最大0.5秒続いたことを表示。画面では変換済みの場合があるため再変換を促さない |

手動変換の範囲照合失敗は、以前は通知せず終了していた。現在は既存の安全な
再照合が失敗した後に原因を分類する。変換要求／選択位置の変更は正常な取消として
通知しない。既に通知されたAPI失敗を後続の範囲照合失敗で上書きしない。
自動変換も汎用の「入力先に接続できませんでした」にまとめず、適用失敗の段階を保持する。
自動判定前の読取不能・不一致は、入力先が最新の文字列をまだ返していない場合にも
起こり得るため、エラーへ昇格させない。メニューの独立した「自動変換の見送り」と
設定画面に理由・文字数・読取長を残し、診断は維持する。
選択位置・入力活動・入力先の変更、Esc、対象外文字、閾値未達はエラーにしない。

同日、最初の診断版へ更新後、利用者から短文でも2文字目くらいでエラーが出ると報告された。
判定前の観測失敗を赤いエラーへ昇格させていた実装を修正した。
この変更は診断の表示区分だけで、原文照合・送信条件・置換条件を緩和しない。
2026-10-07、修正版へ更新後、利用者から2文字目付近のエラーが出なくなり、
従来どおり変換できると報告を得た。短文の誤通知への回帰確認として記録する。
続いて利用者が長文で再現し、以下のメニュー表示をスクリーンショットで報告した。

- 対象121文字／UTF-16 121。
- 失敗段階は「原文確定後の確認」。記録範囲121単位とカーソル直前の全文は両方取得不可。
- 表示されている直近のJev判定は変換対象（スコア0.890／閾値0.60）。
- 原文確定後の文字列を読めないため、結果の適用を中止したことをメニューで確認できた。
- 利用者から「原文のまま変換されなかった」と追加報告を得た。

この失敗段階に到達するコード経路は、変換結果の取得成功後に原文を確定・照合する経路。
今回観測した停止原因は、API通信失敗ではなく確定原文の全文読取不能である。
末尾100単位が現在も読めるかの実測はしていないため、#41と同じ制約との関係は推定に留める。
その後、利用者が案内した手動変換の比較テストを行い、120文字／UTF-16 120で
「変換結果の適用前・範囲照合」「原文を読み取れず、結果を適用していません」を
表示したスクリーンショットを報告した。報告された文章は未変換のローマ字のままだった。
自動の原文確定後と手動の適用前の両方で、全文読取不能を捕捉・表示できた。
自動変換だけの問題や、判定APIのスコア不足とは区別できる。
最後に短文のCtrl＋Jによる変換とCommand＋Zを1回押して原文へ戻る操作を案内し、
利用者から「短文はその通りでした。問題なし」と確認を得た。
この報告は今回の短文の変換・Undoに限定し、全アプリ・全Undo履歴には一般化しない。
現在の入力先での100単位の境界測定は未実施。長文そのものの制約を解消した意味ではない。
入力本文・期待する変換結果はこの記録へ転記しない。

## 入力とプライバシー

- 原文を取得・照合できない範囲を、文字数や末尾の部分一致だけで置換しない。
- 置換効果が拒否されたときに、内部の前回変換が成功したままにならないようにする。
  入力済みの原文を残し、後続の未適用入力は既存の保留文字へ救出する。
- 正常な原文確定・結果置換の2回の書き込み順序は変更しない。
- 手動／自動の結果確認は、書き込んだ結果の記録範囲だけの読み取り。
  最大5回・100ms間隔で、有料判定・変換API・文字の書き込みを繰り返さない。
  手動は即時確認でも一致すれば追加の読み取りを行わない。
  入力・対象・状態の変更時は静かに中止し、確認失敗でも結果を再書き込み／消去しない。
- メニューには原文・候補・周辺文章・キー・応答本文を出さない。診断ログは従来の固定イベントのみ。
  数値の診断表示はメモリのみで保存しない。
  既存の一時デバッグ画面は明示オン・メモリのみ・再起動後オフのまま。

## 自動確認と実機確認を分ける

模擬入力先で99／100／101／200／512文字の全文照合、100単位までしか読めない場合の
取得不能／部分取得の分類、原文と周辺文字の保護、サロゲートペアのUTF-16長、
置換拒否後の状態修復と保留文字救出を確認する。既存の表示上の折り返しの再照合も維持する。
1／2／3／99／100／101／201文字の観測不一致ではエラー・カーソル印・通信が発生せず、
診断だけが保持されること、過去の本当のエラーを消さないこと、次の観測・設定変更で
見送り診断が更新／解除されることも検証する。
模擬通信・専用UserDefaults・模擬Keychainのみを使用し、実APIへテスト入力を送らない。
模擬入力先の書き込み順序は、実アプリのUndoグループ化を保証するものではない。

実機では、機密情報を含まないローマ字を実際に入力し、100文字未満・100文字・100文字超、
折り返しの有無、Ctrl＋Jと自動変換を分けて確認する。手動の比較時は利用者自身が
自動変換を一時的にオフにして途中変換を防ぎ、確認後に元へ戻す。
失敗時にはメニューの段階・原因・文字数を記録し、画面上の変換有無と区別する。
短文の従来動作、成功後のCommand＋Z、Esc・追加入力・フォーカス移動の静かな取消も確認する。
原文を通常のログへ出すことや、確認用にAPIキーを変更・削除することは必要ない。
