# Jevアンビエント変換（#55）

> 2026-10-08：Jev方式は廃止。以下は旧実装とその実機確認の履歴であり、
> 現行の設定・送信方式ではない。[Decisions方式の現行仕様](DECISIONS_CONVERSION.md)を参照。
> 過去の実機確認をDecisions方式の検証済みとは扱わない。

## 状態と参照

2026-10-05、設定画面と入力処理への接続を実装した。模擬テストによる検証済みで、
実機確認の結果は末尾に記録する。利用者から自動送信部分の実装許可を得ている。
自動テストは模擬通信のみで、実機での有効化と入力による確認は利用者が行う。

参照は[Sumibi PR #190](https://github.com/kiyoka/Sumibi/pull/190)の
a909167d18ef28ae26a3129805dde9c1606cd9c0。
Jevは変換タイミングだけを判定する。日本語への変換は既存の変換APIと辞書を使う。

## 設定と送信データ

API設定内の「Jev自動変換の設定…」から設定する。
既定はオフで、全アプリ共通のオン／オフ、専用キー、TypeSafeへの送信同意、
閾値、回数上限、確認付き回数リセットを提供する。
既定値はモデル`jev-latest`、閾値0.8、判定タイムアウト10秒、最大512文字、上限10,000回。
保存済みの回数上限は既定値の変更で上書きしない。
回数上限の矢印操作は1,000回以上・1,000回単位とし、その場で上限だけを保存する。
以前の端数付き設定は操作方向の1,000回単位へ揃える。閾値・キーの編集中の値は保存せず、
累積判定回数もリセットしない。閾値も変更時に自動保存し、キーの入力途中の値は保存しない。
APIキーだけは専用の保存ボタンで確定する。通常設定を保存する共通ボタンは設けない。
既存の変換APIのキーと送信同意も必要になる。

JevのPOST先は`https://api.typesafe.ai/v1/systemone`に固定する。
送信するのはSumibiで編集中の対象、最新操作（1文字または`BACKSPACE` / `EDIT`）、
文脈区分、待機時間。文書全体、周辺文字列、クリップボード、ユーザー辞書はJevへ送らない。
日本語への変換APIには従来どおり変換対象とユーザー辞書を送る。両方に利用料金が生じ得る。

Jev用キーは`org.sumibi.Sumibi-mac.jev-api-key`の独立したKeychain項目で、
端末限定・iCloud同期なし。設定JSONやUserDefaultsには保存しない。
保存済みキーは短い伏せ字で表示し、変更時の入力欄は空にする。
保存失敗時は入力を保持する。同意取消・キー削除では自動変換を無効化する。

回数はインストール単位の累積値で、再起動や入力ソース／アプリ切替ではリセットしない。
送信開始前に予約し、失敗・取消となった試行も含むため、請求回数の厳密な表示ではない。
明示的なリセットでのみゼロにする。リセットしても既発生の利用料金は消えない。
参照実装のバッファ別上限とは異なる、全体の上限である。

## 対象と制限

オン時にアプリ別の許可リストは設けない。ただし安全上、次の条件をすべて満たす
Sumibi自身の単一行の未確定入力だけを対象とする。

- 通常の除外対象（EmacsやSumibi自身の設定画面など）ではなく、Secure Event Inputが無効。
- 最前面の入力先で、未確定範囲の位置と長さを取得でき、選択位置が末尾のカーソルまたは未確定範囲全体と一致する。未確定範囲全体を選択範囲として報告する入力先にも対応する。
- 選択位置が未確定範囲の長さと同じで選択長が0の場合は、未確定文字列内の相対末尾として扱える。ただしその位置が未確定範囲の開始より前にある場合に限る。文書座標で範囲内のカーソルとも解釈できる場合は安全側に見送る。その他の部分選択・範囲外・不明な位置は許可しない。
- 最大512文字。切り詰めない。ASCII英字を含み、許可した英数字・空白・句読点のみで構成される。
- 手動変換待ちや候補選択中ではない。

選択範囲や既に確定した文書から新しく原文を収集しない。
改行、感嘆符、括弧、スラッシュ等を含む入力は対象外。
Emacsの構文解析と同等のコード／コメント／文字列判別は実装しておらず、
送信する文脈区分は`plain`である。単純なコード風文字列が対象になる可能性はある。
独自の機密入力欄をすべて識別できる保証はない。機密情報を入力する前にオフにする。
範囲の位置・長さを取得できないアプリや入力クライアントを頻繁に再生成するアプリでは、安全側に処理を見送る。
「全アプリ対象」は全アプリで動作を保証する意味ではない。

## 非同期処理と置換

新しい入力は待機中の観測を最新1件へ集約する。判定と変換を合わせて同時処理は1件。
取消後も通信が終了するまで処理枠を再利用せず、重複送信を防ぐ。
`.` / `,` / `?` / `。` / `、` / `？`は最低0.5秒待ち、その間の入力で待機を更新する。
判定値が閾値以上のときだけ既存APIへ変換を依頼する。自動再試行はしない。

待機中も入力できる。追加入力、カーソル／入力先移動、候補操作、Esc、手動変換、
設定・同意・辞書の変更で古い応答を適用しない。
判定前・変換前・適用前に入力先、範囲、保持中の原文、選択位置、設定の一致を検証する。
未確定本文をIME経由で取得できる場合は、その本文とも照合する。
本文だけを取得できない場合は、Sumibi自身が保持している未確定入力で判定する。
範囲・選択位置・入力先の確認は省略せず、本文を取得できて不一致なら拒否する。
未確定本文が読めなかった対象は、原文を確定した後の厳密な照合を必須とする。
確定後も原文を読めない、または一致しなければ、結果を書かず確定した原文を残す。
相対末尾形式で確定後も同じ位置が報告された場合は、記録した未確定範囲に確定原文が
一致することを必須とし、同期適用の間だけ文書座標へ正規化する。既存の位置補正が
相対位置を文書位置と誤認し、前方の同じ原文へ移動しないようにする。
前後へ探索して対象を探すのではなく、記録した範囲そのものを照合する。
変換結果は原文を一度確定してから、既存の追跡付き置換処理で適用する。
この経路でも空文字の挿入・貼り付け・追加の確定操作・独自Undoは導入しない。
従来と同じ原文確定・結果置換の2回の書き込みを使う。Undoのまとまり方は実アプリごとに
確認し、利用者の条件としてUndoが悪化する場合はこの読取不能時の方式を採用しない。
句読点は日本語の対応する記号へ整える。空の候補を句読点だけで置き換えない。

設定画面に待機／判定中／変換中の状態、回数、固定のエラー文を表示する。
送信前の安全条件を満たさない場合は「直近の送信見送り理由」を固定文で表示する。
設定画面を開いても直前の理由を維持し、新しい対象の観測や設定変更で解除する。
理由の表示は固定文のみ。選択位置の不一致時は、チェックで実際に使用した未確定範囲と
選択範囲のUTF-16位置・長さを別欄へ表示する。診断用の数値はメモリ上だけで保持し、
ログ・設定・ファイルへの保存やJevへの送信はしない。入力文字列・アプリ名は表示しない。
本文読取で失敗した場合は、要求長と取得長（UTF-16）だけを表示する。
適用失敗は別欄で原文確定前・確定中のセッション変更・確定後の読取不能／不一致・
範囲確認失敗・結果確認失敗に分けて表示する。最初の適用失敗を後段の失敗で上書きしない。
この履歴は後続入力の見送りとは別に、次の適用試行または設定変更までメモリ上で保持する。
確定後の診断は、記録した範囲と手動変換でも使う確定後カーソル直前の範囲について、
読取長と「取得不可・空文字・一致・大文字小文字だけの相違・長さの相違・その他の相違」
だけを表示する。本文を保持せず、ログ・設定・ファイルへ保存しない。
この診断は位置補正や原文不一致の許可を追加するものではない。

利用者がデバッグのための原文表示を明示許可したため、「一時デバッグ」内に
「原文・取得文字列を設定画面に表示」を追加した。既定はオフで、明示オン時だけ、
失敗した適用の保持原文・記録範囲の取得文字列・確定後カーソル直前の取得文字列を
表示する。ログには出さず、設定・ファイルにも保存しない。文字列はプロセスのメモリのみで
保持し、オフ・設定変更・次の適用試行・成功で破棄する。再起動後はオフ。
取得範囲に別の文章を含む可能性があるため、短いダミーのテスト文だけを入力し、
機密入力を避け、確認後はオフにする。照合とUndoの書き込み処理は変更しない。
既存の処理中アイコンとエラー通知にも接続する。
ログは[診断ログの方針](DIAGNOSTIC_LOGGING.md)に従い、固定イベントと分類だけを記録する。
原文、最新キーの本文、判定値、キー、要求・応答本文はログに出さない。

旧Jev通信と設定の実装は廃止し、現在は[DecisionsClient](../Sources/SumibiCore/DecisionsClient.swift)、
[DecisionsCoordinator](../Sources/SumibiIME/Conversion/DecisionsCoordinator.swift)、
[AmbientConversionLifecycle](../Sources/SumibiIME/Conversion/AmbientConversionLifecycle.swift)、
[AmbientResultApplier](../Sources/SumibiIME/Conversion/AmbientResultApplier.swift)。

## 検証と実機確認

Core 12件とIME 58件を追加した。模擬通信・模擬Keychain・専用UserDefaultsで、
設定、要求形式、応答検証、取消、競合、同意、回数上限、範囲検証、置換を確認する。
全体の実行方法は[Tests/README](../Tests/README.md)を参照。
実APIや全アプリでの挙動、安全性を確認済みとはしない。

実機では以下を確認する。送信先と費用を確認した利用者が、設定画面から明示的に有効化する。

- オフの状態で従来の通常変換・候補・Esc・設定と保存済みキーが維持される。
- 専用キーの保存・変更取消・削除、独立した送信同意、オン／オフが動作する。
- テキストエディット等で空白・句読点後の自動変換と、日本語句読点への整形を確認する。
- 判定中の追加入力、カーソル移動、アプリ切替、Esc、手動変換で古い結果が混入しない。
- Undo、句読点の直後に入力を続ける場合、複数の入力先で原文が壊れない。
- 小さい回数上限、通信失敗、同意取消、キー削除で停止・固定エラー表示・手動変換の継続を確認する。

非キー・非アクティブ・クリック透過のパネルを使い、50ms間隔で入力イベント数・前面アプリ・
入力先の同一性・セキュア入力を確認する。新しい入力・停止・対象変更で解除し、古い応答では
表示しない。座標が不明・無効・画面外なら表示を見送り、マウスや過去座標で代替しない。
幾何処理と表示寿命・解除を模擬テストする。実際の位置・入力を妨げないこと・Undoは実機確認する。

利用者がカーソル近傍の「✓」表示を確認し、変換エラーでも近くに別の赤い表示を求めた。
新しい変換エラーの通知時だけ、現在の入力先・前面アプリ・セキュア入力・安全な座標を
確認して赤い円の「!」を約0.6秒表示するよう追加した。自動・手動変換に共通の通知入口を
使うが、表示更新・解除では再表示しない。緑の表示の期限が後から赤を消さないことも
模擬テストし、原文・変換結果・書き込み・送信方式は変えない。赤の実機表示は未確認。
